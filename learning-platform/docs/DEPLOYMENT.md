# تشغيل المنصة على Hostinger

المشروع إضافة مستقلة للموقع الحالي، وليس استبدالًا لمجلد موقع المركز أو لقاعدته. لم يُنفذ نشر على Hostinger أو ترحيل لبيانات المركز أثناء البناء. يُقترح نطاق فرعي `learn.tafaseel-training.com` بعد تأكيده وإعداد SSL.

## المتطلبات

PHP 8.3+ مع PDO وpdo_mysql وmbstring وOpenSSL وfileinfo وcurl وSimpleXML وiconv. MySQL 8 أو MariaDB. بيانات MySQL في ملف PHP خاص. الحد الأقصى لكل ملف 30 MB، والمساحة الإجمالية الافتراضية 2 GB. الفيديو الطويل إلى Bunny Stream برفع مباشر قابل للاستئناف، افتراضيًا حتى 10 GB لكل فيديو بحسب حدود حساب المزود. ويمكن استخدام YouTube أو Vimeo؛ رفع MP4 القصير متاح. المنصة لا تشغّل بث فيديو أو لقاءات مرئية بنفسها.

الواجهة تُبنى مسبقًا ولا تحتاج خادم Node على Hostinger. [دعم MySQL وPDO لدى Hostinger](https://www.hostinger.com/support/which-databases-and-data-tools-are-supported-at-hostinger/).

## تنظيم الملفات

```text
parent-directory/
  public_html/                      # جذر النطاق الفرعي فقط
    index.html
    assets/
    images/
    brand/
    api/index.php
    .htaccess
    .user.ini
  tafaseel-learning-private/         # خارج أي جذر عام
    api.php
    bootstrap.php
    schema.sql
    schema-v2.sql
    vendor/                          # الاعتماديات ضمن الحزمة
    console.php
    config.php
    storage/
```

`public_html/api/index.php` يبحث افتراضيًا عن المجلد الخاص المجاور. إذا كان تنظيم الاستضافة مختلفًا، اضبط `TAFASEEL_PRIVATE_DIR` إلى مساره المطلق في إعدادات الخادم. لا تنقل ملفات الخادم إلى الجذر العام لتجاوز مشكلة المسار.

## خطوات التثبيت

1. خذ نسخة كاملة من الموقع والقاعدة الحالية، وتحقق من إمكانية استعادتها. لا تستخدم قاعدة التسجيل الحالية كقاعدة جديدة للمنصة.
2. أنشئ نطاق التعلم الفرعي من hPanel وفعّل HTTPS. أنشئ قاعدة MariaDB ومستخدمًا يملك صلاحيات على قاعدة المنصة فقط.
3. محليًا: `composer install --no-dev --prefer-dist` ثم `npm ci` ثم `npm run package`. ارفع محتويات `public_html` من الأرشيف إلى جذر النطاق الفرعي، وضع `tafaseel-learning-private` خارجه. لا ترفع المشروع أو `reference` أو `.local` كاملًا.
4. انسخ `config.example.php` إلى `config.php` داخل المجلد الخاص. اضبط `environment=production` و`demo=false` و`origin` إلى رابط النطاق الفرعي بلا شرطة أخيرة. اضبط DSN واسم المستخدم وكلمة مرور القاعدة.
5. ولّد مفتاح التشفير على الاستضافة باستخدام:

```sh
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

احفظ المفتاح في `config.php` فقط، واحتفظ بنسخة منفصلة خاصة. لا ترسله في المحادثة أو Git. فقدانه يمنع قراءة الأرقام والمرفقات المشفرة؛ تغييره لا يعيد تشفير السجلات القديمة.

6. من طرفية Hostinger:

```sh
php /ABSOLUTE/PATH/tafaseel-learning-private/console.php migrate
php /ABSOLUTE/PATH/tafaseel-learning-private/console.php admin admin@YOUR-DOMAIN
```

الأمر الثاني يطلب الاسم وكلمة المرور بإدخال مخفي. لا ينشئ `migrate` أي حسابات أو بيانات توضيحية. لا يوجد مثبّت HTTP عام أو كلمة مرور افتراضية.

7. اجعل صلاحيات المجلد الخاص و`storage` مقتصرة على مستخدم PHP، وملف الإعداد 0600 إن كان تنظيم الاستضافة يدعمه. اختبر أن `config.php` وقاعدة البيانات ومجلد التخزين غير قابلة للوصول عبر HTTP. تحقق من تفعيل `mod_headers` و`mod_rewrite` أو مكافئهما في LiteSpeed. ارفع حد POST إلى 32 MB وmemory_limit إلى 256 MB عبر hPanel إذا لم تطبق `.user.ini`.
8. سجّل دخول المدير، وأكمل المصادقة الثنائية قبل استعمال الأدوات الإدارية؛ تفرض في الإنتاج افتراضيًا. أضف المدربين وراجع الدورات ثم سجّل الطلاب. بالنسبة للقاصر، الاسم والجوال المنفصلان لولي الأمر وموافقة الحفظ مطلوبة.
9. اختبر دورة حقيقية واحدة بحساب طالب تجريبي معتمد: درس، فيديو، ملف، تسليم واجب، تصحيح، اختبار، حضور، شهادة. اختبر من جوال آخر عبر HTTPS. بعدها أضف رابط «المنصة التعليمية» إلى الموقع الأساسي.

## بيانات النظام السابق

المصدر العام للموقع الحالي مختلف عن بعض نسخ GitHub القديمة. في `reference/tafaseel-attendance/integration/tafaseel-core` توجد نسخة مخطط سابقة: `users`, `students`, `courses`, `cohorts`, `registrations`. لا يُفترض تطابقها مع النسخة المنشورة.

أداة `import-legacy.php` تفحص نسخة SQLite متسقة للقراءة فقط وتعرض ملخصًا، ثم تستورد السجلات الأساسية عند طلب `--apply`. كل دفعة تدريبية تتحول إلى دورة مستقلة باسمها ورقم مجموعتها، لتفادي خلط تسجيلات المجموعات. لا تستورد كلمات مرور الإدارة القديمة أو ترسل أي بيانات إلى الخارج. حسابات الطلاب المستوردة موقوفة حتى مراجعة ميلاد الطالب وبيانات ولي الأمر وتعيين كلمة مرور من الإدارة. تُحفظ أرقام التواصل القديمة كبيانات مشفرة تحتاج تحديد صفتها، ولا تُفترض أنها أرقام أولياء الأمور.

```sh
php /PRIVATE/import-legacy.php /PRIVATE/verified-snapshot.sqlite
php /PRIVATE/import-legacy.php /PRIVATE/verified-snapshot.sqlite --apply
```

نفّذ الاستيراد أولًا في قاعدة اختبار، وقارن الأعداد والعينات مع النظام القديم. لا يُنقل الحضور أو التحصيل أو الرسائل من التطبيق الآخر بهذه الأداة. لا يوجد ربط حي أو مزامنة ثنائية تلقائية بين النظامين.

## النسخ الاحتياطية والاستعادة

استخدم نسخ Hostinger للقاعدة، ونسخًا دورية متناسقة لمجلد `storage/files` وإعداد التشفير. احفظ المفتاح في مكان منفصل. لا تنسخ جلسات المتصفح إلى بيئة استعادة عامة. جرّب الاستعادة إلى نطاق خاص، وقارن ملفًا مشفرًا وشهادة وتسليمًا. للتطوير SQLite، الأمر `console.php backup PRIVATE_DIRECTORY` ينشئ لقطة قاعدة متسقة؛ يجب ضم الملفات المشفرة والمفتاح إلى سياسة النسخ.

للتراجع، أزل رابط المنصة أو أوقف نطاقها الفرعي؛ لا تحذف البيانات أو تستبدل قاعدة الموقع القديم. لا تعِد إعداد تجربة محلية في الإنتاج.

## استعادة حساب فقد المصادقة الثنائية

من طرفية الاستضافة الخاصة فقط: `php console.php mfa-reset ACCOUNT_EMAIL`. يطلب كلمة مرور المدير الحالي قبل التعطيل، ويسجل العملية ويبطل الجلسات. على صاحب الحساب إعادة التفعيل من صفحة الأمان. لا يوجد تعطيل عبر رابط عام.

## تفعيل خدمات الإصدار الثاني

اتبع [دليل الخدمات](INTEGRATIONS.md). المكتبات جاهزة داخل المجلد الخاص؛ لا تحتاج Composer على Hostinger إن رفعت الأرشيف المكتمل. شغّل `php /PRIVATE/console.php doctor` لعرض حالة الإعداد دون أسرار.

لرسائل الغياب، أضف مهمة hPanel كل دقيقة بالأمر التالي، مع استبدال المسار الخاص والتحقق من مسار PHP 8.3 الفعلي لدى استضافتك:

```sh
php /PRIVATE/console.php worker >> /PRIVATE/worker.log 2>&1
```

راقب آخر تشغيل من «الخدمات والتشغيل»، وحالات «غير مؤكدة» و«فشل» من «رسائل الغياب». لا تشغّل إعادة إرسال آلية عمياء. عامل واحد يعالج حتى 25 إشعارًا في الدورة، ويستخدم حجز سجلات لمنع ازدواج الإرسال عند تداخل المهام. سجلات التشغيل يجب أن تبقى خارج الجذر العام مع تدويرها.

نسخ S3 وBunny تحتاج سياسة استبقاء ونسخ لدى المزود؛ نسخة القاعدة وحدها لا تسترجع الملفات أو الفيديو. تأكد من مناطق استضافة البيانات وشروط الخدمات المناسبة للمركز قبل نقل بيانات طلاب حقيقية. نوع باقة Hostinger الحالية غير مؤكد؛ يجب التحقق من cron وموارد PHP وقاعدة البيانات والمساحة قبل النشر النهائي.
